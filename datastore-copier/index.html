Read-only Schema Comparison & Datastore Management

1. Authenticate

gcloud auth print-access-token

The token is held in memory only, sent only to allowlisted Google API origins, and discarded when this page closes.

2. Select Operation Mode

Read-only mode. The comparator only lists datasets/tables and reads schema metadata. It cannot create, copy, update, override, or delete BigQuery resources.
Detailed Breakdown: What Is vs. What Isn't Copied BigQuery Data Transfer Spec

When copying Scheduled Queries in the GCP Infrastructure Manager, not everything is copied blindly. The portal copies the functional definition so the query can run in the destination project, but intentionally excludes system-generated runtime metadata, credentials, and project-bound dependencies.

Configuration Component Copied? Details & Behavior
Display Name (displayName) ✅ Yes Copied exactly as named in the source project.
Cadence / Frequency (schedule) ✅ Yes The recurrence pattern (e.g., every 24 hours, every day 02:00, 1st,15th sunday 14:00).
Destination Dataset (destinationDatasetId) ✅ Yes Name of the destination dataset in the target project.
SQL Query Text (params.query) ✅ Yes (As-Is) The exact SQL statement. (See critical notice below regarding hardcoded project IDs).
Destination Table Template (params.destination_table_name_template) ✅ Yes The destination table pattern (e.g. daily_stats_{run_date}).
Write Disposition (params.write_disposition) ✅ Yes WRITE_TRUNCATE, WRITE_APPEND, or WRITE_EMPTY.
Partitioning Field (params.partitioning_field) ✅ Yes Partition column if the target table is partitioned.
Resource ID & ARN (name) ❌ No GCP generates a new unique resource ID in the destination project (projects/{target-pid}/locations/{loc}/transferConfigs/{new_id}).
Query Ownership / Credentials (userId) ❌ No GCP automatically binds ownership to the authenticated operator / service account executing the copy in the destination project.
Historical Run Logs & Execution States ❌ No Past execution history, audit logs, and run error states remain in the source project; the new query starts fresh.
Pub/Sub Notification Topics (notificationPubsubTopic) ❌ No Excluded to prevent cross-project permission errors (source Pub/Sub topic ARNs are tied to the source project).
Email Failure Alerts (emailPreferences) ❌ No Excluded; notifications should be configured per destination environment.
Schedule Start / End Bounds (scheduleOptions) ❌ No Start and end bounds are not carried over; the query starts active upon creation.
⚠️ Important Notice on SQL Query Content (params.query)

The query SQL string is copied verbatim. If your source query references fully-qualified table paths such as: 

SELECT user_id, amount 
FROM `source-project-prod.analytics.orders`

The copied query in the destination project will still point to source-project-prod unless you update the SQL reference. Always verify that dataset and project references inside the query body match the destination project environment.

GCP Audit Logging Notice

Operations that need to be enabled (Data Access Logs)

Writing or overwriting entities in Datastore uses the Commit API (under google.datastore.v1.Datastore.Commit). To log these actions:

  1. Go to the GCP Console.
  2. Navigate to IAM & Admin > Audit Logs.
  3. Select the Cloud Datastore API from the list of services.
  4. Check the Data Write (for creations, updates, overwrites, and deletes) and/or Data Read (for lookups and queries) audit log types and save.
