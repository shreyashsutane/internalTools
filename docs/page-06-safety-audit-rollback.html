01 Pre-Mutation Snapshot Architecture

Every operation that writes or overwrites data in Google Cloud adheres to a strict protocol:

  1. Target Discovery: The client reads existing target entities before generating mutations.
  2. Snapshot Packaging: If entities already exist in the target, their full JSON structure is compressed into a prevState payload.
  3. Atomic Save: An audit record with status IN_PROGRESS is committed to Cloud Firestore *before* the first mutation RPC is sent to Google Cloud.
  4. Safe Execution: If the network drops or the browser crashes mid-copy, the snapshot is already preserved in Firestore and can be reverted from the SuperAdmin console.

02 Partial-Restore Permission Fallback

In strict enterprise GCP environments, operators are frequently granted create and update permissions, but denied datastore.entities.delete.

If an operator triggers a rollback without delete permissions, our revert engine catches the 403 PERMISSION_DENIED error, automatically falls back to restoring overwritten entities via upsert, reports the status as PARTIAL, and outputs the exact leftover entity keys for an administrator to clean up.
