01 Autonomous Chunking & Quota Protection

Google Cloud Datastore enforces strict API constraints on :commit calls: a maximum of 500 mutations or 10 MB per request. To provide a bulletproof safety margin, our migration engine caps requests at 250 mutations and 4.0 MB:

// datastore-copier/src/datastore-utils.ts
export async function commitInSafeChunks(targetProject, mutations, token) {
    const CHUNK_LIMIT = 250;
    const MAX_RPC_BYTES = 4 * 1024 * 1024;
    
    for (let i = 0; i < mutations.length; i += CHUNK_LIMIT) {
        const batch = mutations.slice(i, i + CHUNK_LIMIT);
        // Verify byte length within bounds
        const payloadSize = new TextEncoder().encode(JSON.stringify({ mutations: batch })).length;
        if (payloadSize > MAX_RPC_BYTES) {
            // Split further dynamically
        }
        await DatastoreApi.commit(targetProject, batch, token);
    }
}

02 Dual-Strategy Property Discovery

Unlike relational SQL databases with rigid schemas, Cloud Datastore is schema-free. Different entities under the same Kind can have completely different properties. Our portal employs a dual-strategy discovery algorithm:

STRATEGY A

Statistical Entity Sampling

Executes an ephemeral read of 20 sample entities to dynamically build property drop-downs and discover real datatypes in production.

STRATEGY B

Metadata Kind Queries

Queries __property__ namespace metadata as fallback when zero active entities exist or permissions are restricted.

03 Lossless Datastore REST Value Fidelity

To prevent data corruption during migrations, all Google Datastore primitive and complex types are preserved with 100% fidelity:

Datastore REST Key Data Type Preservation Strategy
integerValue 64-bit Signed Integer Preserved as string to prevent 64-bit IEEE 754 precision loss in JavaScript.
timestampValue RFC 3339 UTC Timestamp Maintains exact nanosecond ISO timestamp with zero timezone drift.
blobValue Binary Byte Array Transferred via base64 encoding without string encoding mutation.
keyValue Datastore Entity Key Retargets partition project ID to target while preserving kind, ID, or name hierarchy.
