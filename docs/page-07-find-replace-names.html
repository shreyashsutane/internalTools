01 Dynamic Display Name Extraction Hierarchy

Raw Datastore entity IDs (such as 5629499534213120) are unreadable to human operators. To eliminate guesswork, the portal inspects properties in a prioritized cascade to find the best human-readable identifier:

1. chainName → Data pipeline workflows
2. referenceName → Schema definitions
3. displayName → UI configurations
4. jobName / title → Scheduled tasks
5. name → Named Datastore keys
6. __key__.id → Numerical key fallback

02 Scoped Property Targeting vs Global Substitution

Operators can constrain Find & Replace to a specific property (e.g. only inside database_url or topic_arn), preventing accidental regex collateral damage across unrelated fields.
