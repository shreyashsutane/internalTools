02 The Four-Tier Security Enclave

Unlike traditional migration tools that route corporate data through an intermediary server, GCP Tools Portal utilizes a Zero-Knowledge Client Enclave Architecture. Your data never touches our backend:

T1

Tier 1: Static Edge CDN (Firebase Hosting)

Fastly AnyCast CDN

Serves immutable static HTML, minified JS, and stylesheets with strict browser security headers (CSP, HSTS 31536000s, X-Frame-Options: DENY, and Cache-Control: no-store on app routes).

Headers: Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; upgrade-insecure-requests
T2

Tier 2: Client Execution Enclave (Browser RAM)

Sandboxed Memory

The operator's Google OAuth Bearer Token resides purely in a volatile TypeScript module closure (State.token). It is completely erased upon page reload or tab closure.

Storage: localStorage = NONE | sessionStorage = NONE | Cookies = NONE | URL query strings = NONE
T3

Tier 3: Direct GCP REST Mesh (Browser ↔ Google Cloud)

Peer-to-Peer TLS 1.3

Schema queries, entity lookups, and batch commits travel directly over HTTPS from the operator's browser to datastore.googleapis.com and bigquery.googleapis.com.

Direct Endpoints: https://datastore.googleapis.com/v1/projects/{id}:runQuery & :commit
T4

Tier 4: Centralized Audit & Safety Bus (Cloud Functions + Firestore)

Least-Privilege Backend

A dedicated serverless microservice (auditApi) verifies tokens via Google OpenID, enforces transaction rate-limits (120 req/min), and stores immutable audit snapshots. Direct client writes to Firestore are blocked.

IAM Identity: audit-logger@gcp-tools-portal.iam.gserviceaccount.com (512 MiB RAM, max 10 instances)

05 GCP Quota Compliance & Operational Boundaries

To prevent throttling, quota exhaustion, and memory spikes during heavy production migrations, the portal strictly enforces the following boundary limits:

Parameter / Constraint Enforced Limit Architectural Rationale
Commit Mutations per RPC 250 Mutations Strictly adheres to Google Cloud Datastore's 500-mutation limit with 50% safety buffer.
Max RPC Request Payload 4.0 MB Prevents HTTP/2 stream buffer overflow and gRPC payload rejection from GCP Datastore API.
Entity Lookup Batch Size 50 Entities Optimizes latency and renders real-time progressive UI updates in table views.
Audit Snapshot Body Limit 700 KB Ensures pre-mutation state fits comfortably inside Firestore's 1 MB document limit.
Serverless Memory & Timeout 512 MiB / 60s Cloud Functions runtime bounds prevent runaway billing and unmanaged background execution.
Rate Limiting Window 120 Requests / Min Sliding-window counter keyed by SHA-256 hashed identity prevents credential stuffing abuse.
