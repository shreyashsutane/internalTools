How Operational Email Notifications Work: From Click to Inbox

A clear, visual, beginner-friendly walkthrough explaining how the system automatically detects user actions (login, entity comparison, database copying, and rollback) and instantly sends a formatted email alert to shreyashs14102002@gmail.com safely without exposing any passwords.

01 The 30-Second Beginner Summary (The Post Office Analogy)

If you are new to web development or cloud computing, think of how a secure postal delivery service works:

1. You Perform an Action

You click "Verify Token", "Analyze Entities", or "Copy Entities" in the browser. Your browser writes a short message saying: "Hey, operator X just copied 42 rows!"

2. The Cloud Security Guard

Our serverless Cloud Function acts as an honest security guard. It checks with Google to prove who you really are, writes an unalterable audit log, and grabs the email template.

3. The Secure Delivery

The server takes the Gmail App Password from a digital vault (GCP Secret Manager), connects to Gmail via Nodemailer, and drops the email right into your inbox.

Why couldn't the browser just send the email directly?
❌ Sending from the Browser (Unsafe):

Anyone could right-click "Inspect" on the web page to steal your Gmail password, or forge a fake email pretending someone else copied the database!

✅ Our Serverless Backend (100% Safe):

Your Gmail password is kept completely hidden in Google Secret Manager. The backend asks Google directly for the verified operator email address.

04 Frequently Asked Security Questions (Beginner FAQ)

1 How does the system know the operator's REAL email address?

When the user logs in, they supply a temporary Google Cloud Bearer token. When a request reaches our Cloud Function, the server does not trust any email string sent in the body. Instead, it contacts Google’s OAuth token server (https://openidconnect.googleapis.com/v1/userinfo) with the token. Google responds with the authoritative user profile email.

2 Where is my Gmail App Password stored?

Your password is never saved in the source code or git repository. It is saved in Google Cloud Secret Manager under ALERT_GMAIL_APP_PASSWORD. Only our Cloud Function's dedicated service account has permission to read it during runtime execution.

3 What happens if Gmail SMTP is slow or times out? Will my database copy fail?

No. The email dispatcher is wrapped in an asynchronous non-blocking error handler: sendMutationAlertEmail().catch(...). If Gmail is unreachable, the audit record and database operations still complete with 100% success.

4 How do we prevent hackers from injecting malicious scripts into emails?

All dynamic parameters (project names, kind names, error logs) pass through our escapeHtml() sanitizer function, which converts HTML reserved characters (< ➔ &lt;, > ➔ &gt;, " ➔ &quot;) to make email rendering completely safe.
