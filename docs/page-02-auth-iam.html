01 The Zero-Persistence Memory Security Policy

Most web-based cloud administration tools store sensitive OAuth credentials in localStorage or browser cookies. If malicious browser extensions, XSS scripts, or shared device users inspect the machine, these tokens can be exfiltrated.

Strict Ephemeral Memory Guarantees

  • 1. Volatile Memory Closure: The token is saved solely in a module-scoped variable (State.token). No browser persistence API (localStorage, sessionStorage, IndexedDB, CacheAPI) is ever touched.
  • 2. No URL Leakage: Tokens are never attached as query parameters or hash fragments in HTTP requests. They are transmitted strictly via the HTTP Authorization: Bearer header.
  • 3. Instant Tab Evaporation: When the browser tab is closed, refreshed, or navigated away from, the JavaScript heap is immediately freed by the browser garbage collector, destroying the token forever.

03 Server-Side Tokeninfo & Anti-Spoofing Pipeline

When audit records or rollback requests are submitted, the backend microservice (auditApi) does not accept or trust any client-submitted email address. Instead, the verified identity is extracted securely on Google's OpenID servers:

// functions/lib/audit-core.js
const verifyGoogleIdentity = async token => {
    const response = await fetch('https://openidconnect.googleapis.com/v1/userinfo', {
        headers: { Authorization: `Bearer ${token}` },
        cache: 'no-store',
        redirect: 'error'
    });
    if (!response.ok) {
        throw new AuditRequestError(401, 'INVALID_TOKEN', 'Google access token is invalid or expired.');
    }
    return normalizeVerifiedIdentity(await response.json());
};
