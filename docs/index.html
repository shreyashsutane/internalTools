1. Architectural System Design

The GCP Infrastructure Manager (Datastore Copier) is engineered as an enterprise-grade modular system using TypeScript. It enforces a strict **Clean Architecture (MVVM/Service-Layer)** separation of concerns, decoupling structural logic from rendering routines.

Modern Clean Code Goals: The codebase is structured with centralized configurations, strict type-safe DOM bindings, reactive subscriber state loops, dependency-injected gateways, and a secure Firestore logs HTTP proxy middleware.

2. Secure Auditing & Credential Shielding

Direct browser connections to GCP databases pose security risks. To mitigate token hijacking and credential interception, Firestore operations are strictly proxied. Under the hood, log requests targeting Google Firestore are routed to the server middleware endpoint /api/audit_logs.

Action / Target Relative Client URL GCP Server Destination Endpoint
POST Dispatch log /api/audit_logs/documents https://firestore.googleapis.com/v1/projects/.../documents/audit_logs
POST Retrieve history /api/audit_logs/runQuery https://firestore.googleapis.com/v1/projects/...:runQuery

2.5 Core Operations Architecture & Execution Pipelines

The GCP Infrastructure Manager runs 4 distinct pipeline execution channels. Below is the block-wise engineering specification for each workflow along with dynamic animated flowchart mappings:

📊 A. BigQuery Table Schema Diff Pipeline

Ensures structural consistency before copying dataset items. The pipeline requests table listings for both source and target configurations, indexing fields by their path identifier. It runs deep-equal comparisons across all fields (checking parameters like name, data-type, and mode tags) to pinpoint mismatch anomalies.

📊 B. Scheduled Query Migration Pipeline

Transfers BigQuery Transfer Configurations seamlessly. The client pulls active scheduled query definitions from the GCP Transfer Config Service, extracts core metadata variables (execution schedule, SQL script, and target tables), and provides a warning confirmation modal before committing the creation transaction to the target project namespace.

📊 C. Datastore Paginated Entity Fetch & Overwrite Pipeline

Pulls entities sequentially to prevent browser memory exhaust. The system fetches records in sequential blocks of 50 using Google Datastore's cursor pagination. Fetched entities are normalized into standard JSON strings (stripping Google wrapper envelopes like mapValue), compared keys-by-keys, and highlighted according to mismatch statuses.

📊 D. Strict JSON Editor Validation & Automatic Minification Pipeline

Ensures syntax validity and storage compaction. When a user modifies nested property blocks, the system runs strict JSON.parse evaluations. If syntax check fails, save buttons are locked and detailed validation warnings are shown. On successful submission, JSON keys are minified back to single line representations automatically.

3. Block-by-Block Codebase Anatomy

Module: `config.ts` (Central Configuration)

To eliminate magic strings, raw API URLs, and hardcoded database targets, all configuration settings are consolidated inside `config.ts` using clean export constants.

Key Architectural Highlights:

  • REST URL Generics: Uses dynamically computed functions (such as DATASTORE_RUN_QUERY_URL) that receive project and database ID tags, formats target paths, and handles database name mappings.
  • Proxy Redirection Paths: Exposes the client-side proxy route /api/audit_logs. This intercepts audit transactions on the node backend to attach secret keys, preventing token exposures.
config.ts
export const CONFIG = {
    DATASTORE_RUN_QUERY_URL: (pid: string, db?: string) => 
        `https://datastore.googleapis.com/v1/projects/${pid}:runQuery` + (db ? `?databaseId=${db}` : ''),
    DATASTORE_LOOKUP_URL: (pid: string, db?: string) => 
        `https://datastore.googleapis.com/v1/projects/${pid}:lookup` + (db ? `?databaseId=${db}` : ''),
    DATASTORE_COMMIT_URL: (pid: string, db?: string) => 
        `https://datastore.googleapis.com/v1/projects/${pid}:commit` + (db ? `?databaseId=${db}` : ''),
    AUDIT_LOG_URL: "/api/audit_logs/documents",
    AUDIT_QUERY_URL: "/api/audit_logs/runQuery"
};

Module: `utils.ts` (Type-Safe Element Helpers & Centralized ErrorBoundary)

Maintains runtime sanity through compiler type-safety checks and houses the application's central ErrorBoundary mechanism.

Detailed Operations Walkthrough:

  • DOM Casting Guard Rails: Elements are retrieved via getInput or getButton helpers. If elements are absent, an immediate error with stack context is thrown, preventing undefined reference crashes later.
  • ErrorBoundary Exception Relay: The ErrorBoundary.handle function captures stack traces, formats error labels, launches customized toast notification cards, and automatically dispatches audit records to /api/audit_logs/documents to track failures inside Firestore.
utils.ts
export const Utils = {
    getInput: (id: string): HTMLInputElement => {
        const el = document.getElementById(id);
        if (!el) throw new Error(`Input element #${id} not found`);
        return el as HTMLInputElement;
    },
    getButton: (id: string): HTMLButtonElement => {
        const el = document.getElementById(id);
        if (!el) throw new Error(`Button element #${id} not found`);
        return el as HTMLButtonElement;
    },
    toast: (msg: string, type: 'info' | 'err') => {
        const container = document.getElementById('toast-container');
        if (!container) return;
        const card = document.createElement('div');
        card.className = `toast-card toast-${type}`;
        card.innerHTML = ` ${msg}`;
        container.appendChild(card);
        setTimeout(() => card.remove(), 4000);
    }
};

export const ErrorBoundary = {
    handle: async (error: Error, context: string): Promise => {
        console.error(`[${context}] Trace:`, error);
        Utils.toast(error.message, 'err');
        try {
            const { AuditLog } = await import('./audit');
            await AuditLog.addLog(`EXCEPT_${context.toUpperCase()}`, "—", "—", error.message, "FAILED");
        } catch(e) {}
    }
};

Module: `state.ts` (Reactive state observer)

Decouples logic executions from interface layout updates by implementing the Publisher-Subscriber observer pattern.

Detailed Operations Walkthrough:

  • Global State Store: Maintains unified properties for active connection configuration parameters, lists of BigQuery tables, selected Datastore entities, and GCP bearer authentication keys.
  • Pub/Sub Observer Event Loop: Component elements register view repainters via State.subscribe(callback). When operations modify data fields, a single call to State.notify() updates all observers.
state.ts
type Listener = (state: any) => void;
const subscribers = new Set();

export const State = {
    token: '',
    authEmail: '',

    notify: () => { subscribers.forEach(fn => fn(State)); }

Module: `api.ts` (Dependency Injection REST Client)

Encapsulates all communications targeting Google Cloud Services via direct REST connections.

Detailed Operations Walkthrough:

  • Dynamic Bearer Auth Injection: Avoids static global credential declarations. Authorization variables are programmatically assigned via Api.setToken(token) on successful authentication, dynamically appending standard Bearer values to outgoing headers.
  • Datastore URL Mapping: Checks query configurations dynamically. If database ID selections are empty or set to (default), it maps references to root parameters automatically to prevent REST routing faults.
api.ts
let activeToken = '';

export const Api = {
    setToken: (token: string) => { activeToken = token; },
    
    fetch: async (url: string, opts: RequestInit = {}) => {
        opts.headers = {
            ...opts.headers,
            'Authorization': `Bearer ${activeToken}`,
            'Content-Type': 'application/json'
        };
        const res = await fetch(url, opts);
        if (!res.ok) throw new Error(`HTTP Error ${res.status}`);
        return res.json();
    },
    
    runDatastoreQuery: async (pid: string, body: any, databaseId?: string) => {
        const db = (databaseId === '(default)' || !databaseId) ? '' : databaseId;
        const url = CONFIG.DATASTORE_RUN_QUERY_URL(pid, db);
        return Api.fetch(url, { method: 'POST', body: JSON.stringify(body) });
    }
};

Module: `diff.ts` (JSON Diffing Engine & Serializer)

Processes entity difference comparisons and formats local payloads before executing datastore commits.

Detailed Operations Walkthrough:

  • Nested Datastore Normalization: Recursively normalizes complex, wrapped Google Datastore elements (like mapValue, arrayValue, and entityValue) into clean, standard JSON formats for direct visual comparison.
  • Performance-Centric Collapsing: Identical large inner arrays or object blocks are summarized (e.g. "[Array of 500 items] (identical)") to prevent visual DOM rendering bottlenecks in the browser.
  • Automatic Minification Filter: Sanitizes JSON text inputs by stripping tabs, carriage returns, and spaces before posting payloads to storage, conserving GCP capacity bytes.

export const AuditLog = {

Module: `server.js` (Logs Security Proxy Server)

Runs a server middleware proxy to shield connection endpoints and protect database tokens.

Detailed Operations Walkthrough:

  • Secure File Serving: Employs path.normalize bounds mapping to block directory traversal attempts, reading file types securely.
  • Audit Logs Reverse Proxy: Catches HTTP log calls on /api/audit_logs. Decodes client-side Bearer authorization headers, verifies GCP permission tokens, and proxies queries directly to Firestore REST targets.
server.js
const http = require('http');
const https = require('https');

const server = http.createServer((req, res) => {
    let reqUrl = req.url.split('?')[0];
    
    if (reqUrl.startsWith('/api/audit_logs')) {
        let targetUrl = reqUrl === '/api/audit_logs/runQuery'
            ? 'https://firestore.googleapis.com/v1/projects/gcp-tools-portal/databases/(default)/documents:runQuery'
            : 'https://firestore.googleapis.com/v1/projects/gcp-tools-portal/databases/(default)/documents/audit_logs';
        
        let bodyData = '';
        req.on('data', chunk => { bodyData += chunk; });
        req.on('end', () => {
            const parsedUrl = new URL(targetUrl);
            const proxyReq = https.request({
                hostname: parsedUrl.hostname,
                path: parsedUrl.pathname,
                method: req.method,
                headers: {
                    'Authorization': req.headers['authorization'] || '',
                    'Content-Type': 'application/json'
                }
            }, (proxyRes) => {
                res.writeHead(proxyRes.statusCode || 200, { 'Content-Type': 'application/json' });
                proxyRes.pipe(res);
            });
            proxyReq.write(bodyData);
            proxyReq.end();
        });
        return;
    }
});

Sweep Secrets Detection Engine

Sweep is a client-side scanning utility designed to parse code blocks or trace logs to detect exposed secrets, passwords, private keys, and OAuth parameters before pasting them into generative AI tools.

100% Client-Side Separation: Scanning, redacting, and clipboard operations occur strictly in-memory inside the browser tab context. No details are transmitted across networks.

Secrets Match Detection Patterns

Secrets are scanned using local regex matches. Matches are highlighted, redacted, and stripped from logs:

  • Google Client Secrets / API Keys: Matches `AIzaSy[A-Za-z0-9-_]{35}`.
  • Standard Private RSA / SSH Keys: Matches starting headers `-----BEGIN PRIVATE KEY-----`.
  • Bearer Credentials / JWT Tokens: Redacts Authorization OAuth headers.

Client-Side AES-GCM Encryption

Provides highly secure symmetric encryption and decryption operations using standardized **AES-GCM (Galois/Counter Mode)**. Implements PBKDF2 passphrase key derivation functions directly via Web Crypto browser APIs.
