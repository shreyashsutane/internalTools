                    01
                    Datastore Commit API Architecture
                


                

                    In Google Cloud Datastore (and Cloud Firestore in Datastore mode), all creations, overwrites, updates, and deletions are executed via the atomic Commit API (method: google.datastore.v1.Datastore.Commit).
                


                

                    

                        
ENDPOINT

                        

                            POST https://datastore.googleapis.com/v1/projects/{projectId}:commit
                            
Used for default database ((default)). To target a named database, append ?databaseId={databaseId}.

                        

                    

                    

                        
MODE

                        

                            "mode": "NON_TRANSACTIONAL"
                            
Executes mutations directly without requiring a preceding beginTransaction handshake, maximizing throughput for bulk operations.

                        

                    

                    

                        
BATCHING

                        

                            MAX 500 MUTATIONS / REQUEST
                            
Google limits individual commit requests to 500 mutations or 10MB. Our portal automatically chunks large selections into safe 250-entity batches.

                        

                    

                

            


            
            

                

                    02
                    The Create & Update cURL: upsert
                


                

                    When copying entities between projects in Datastore Copier (or saving inline property modifications), we use the upsert mutation.
                


                

                    
                    Why upsert instead of insert or update?

                    • If the entity does not exist in the target project, upsert creates it.

                    • If the entity already exists, upsert completely overwrites it.

                    • This guarantees atomic execution without failing on ALREADY_EXISTS (which insert produces) or NOT_FOUND (which update produces).
                


                
                

                    

                        
                             Verified Production cURL (Create / Update)
                        
                        
                    

                    
curl -X POST "https://datastore.googleapis.com/v1/projects/TARGET_PROJECT_ID:commit"   -H "Authorization: Bearer $(gcloud auth print-access-token)"   -H "Content-Type: application/json"   -d '{
    "mode": "NON_TRANSACTIONAL",
    "mutations": [
      {
        "upsert": {
          "key": {
            "partitionId": {
              "projectId": "TARGET_PROJECT_ID",
              "namespaceId": ""
            },
            "path": [
              {
                "kind": "assetmaster",
                "id": "4807328926793728"
              }
            ]
          },
          "properties": {
            "assetName": {
              "stringValue": "Dummy Asset 68"
            },
            "environment": {
              "stringValue": "prod"
            },
            "status": {
              "stringValue": "ACTIVE"
            },
            "replicas": {
              "integerValue": "3"
            },
            "isActive": {
              "booleanValue": true
            },
            "lastUpdated": {
              "timestampValue": "2026-09-05T14:30:00Z"
            }
          }
        }
      }
    ]
  }'

                

            


            
            

                

                    03
                    The Revert Deletion cURL: delete
                


                

                    During a 1-Click Rollback, our portal examines the pre-mutation audit record:
                


                

                    
Reverting Newly Created Entities:

                    
If an entity did NOT exist in the target before the copy operation, copying it introduced a brand-new record. Reverting requires issuing a delete mutation to remove it cleanly.

                    
CRITICAL: For a delete mutation, Datastore requires ONLY the key. Do NOT send properties!

                


                
                

                    

                        
                             Verified Production cURL (Revert Delete)
                        
                        
                    

                    
curl -X POST "https://datastore.googleapis.com/v1/projects/TARGET_PROJECT_ID:commit"   -H "Authorization: Bearer $(gcloud auth print-access-token)"   -H "Content-Type: application/json"   -d '{
    "mode": "NON_TRANSACTIONAL",
    "mutations": [
      {
        "delete": {
          "partitionId": {
            "projectId": "TARGET_PROJECT_ID",
            "namespaceId": ""
          },
          "path": [
            {
              "kind": "assetmaster",
              "id": "4807328926793728"
            }
          ]
        }
      }
    ]
  }'

                

            


            
            

                

                    04
                    Restoring Overwritten Entities in Revert
                


                

                    What if the entity already existed in the target before the copy, and was overwritten?
                


                

                    
1. In our pre-flight backup, the portal captured the full prior snapshot: { action: 'upsert', prevEntity: { properties: {...} } }.

                    
2. When you click Revert Operation, the engine extracts item.prevEntity and issues an upsert mutation restoring all original properties and values back to the pre-mutation state.

                    
3. Enterprise IAM Fallback: If an operator triggers a rollback without datastore.entities.delete permissions, the revert engine catches the 403 PERMISSION_DENIED error, automatically falls back to restoring overwritten entities via upsert, marks the audit log as PARTIAL, and itemizes leftover newly-created keys for admin attention.

                    05
                    Datastore Property Value Types Cheat Sheet
                


                

                    When writing properties in Datastore Commit payloads, every value must use its exact typed object key:
                


                

                    

                        
                            

                                Datastore Type
                                JSON Property Key
                                Payload Syntax Example
                            

                        
                        
                            

                                String
                                stringValue
                                {"stringValue": "My Value"}
                            

                            

                                Integer (64-bit)
                                integerValue
                                {"integerValue": "12345"} (must be string-quoted)
                            

                            

                                Double / Float
                                doubleValue
                                {"doubleValue": 99.95}
                            

                            

                                Boolean
                                booleanValue
                                {"booleanValue": true}
                            

                            

                                Timestamp
                                timestampValue
                                {"timestampValue": "2026-09-05T14:30:00Z"}
                            

                            

                                Null
                                nullValue
                                {"nullValue": "NULL_VALUE"}
                            

                            

                                Array
                                arrayValue
                                {"arrayValue": {"values": [{"stringValue": "v1"}]}}
                            

                            

                                Embedded Entity
                                entityValue
                                {"entityValue": {"properties": {...}}}
